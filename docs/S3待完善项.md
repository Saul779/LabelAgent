## 概述

S3 主流程（感知 → 召回 → 语义提议 → 归一 → 预校验 → 落库 → 发布）已实现并可本地演示。以下三项为**有意默认保守**或**依赖产品/安全决策**的待完善点，不影响 MVP 对已有词表标签的打标演示，但会限制「新标签自动入库」和「远程媒体输入」等生产场景。

## S3-P1：`auto_create_unmatched` 默认关闭

### 含义

当 LLM 提议的标签在词表中**无匹配**（`tag_id=None` 且携带 `new_tag_request`）时，`TagCommitter` 是否自动调用 Tag Service **创建新标签**。

当前配置与行为：

- `configs/base.yaml` → `scene.s3.auto_create_unmatched: false`
- `TagCommitter.commit()` 在 `auto_create=False` 时**直接跳过**所有 `new_tag_request`，结果中不会出现 `source=created` 的标签
- 创建逻辑本身已实现：查重 → 幂等键 → `create_tag` → 返回 `TagResult(source="created", vector_state=PENDING)`

### 相关代码

| 位置 | 说明 |
|------|------|
| `configs/base.yaml` | `scene.s3.auto_create_unmatched` |
| `src/label_agent/bootstrap/mvp_scene_factory.py` | `build_s3_handler()` 读取配置并注入 `TagCommitter` |
| `src/label_agent/resolution/tag_committer.py` | 第 57–59 行：关闭时跳过新标签创建 |
| `tests/integration/scenarios/test_s3_pipeline.py` | `test_s3_pipeline_falls_back_and_skips_new_tag_when_auto_create_disabled` |

### 为何 MVP 默认关闭

1. 本地演示使用 `FixtureTagServiceClient`，开启创建会污染 fixture 词表或产生不可预期副作用。
2. 新标签创建会触发异步向量闭环（`TagCreated` → `VectorWorker` → Milvus → `vector_state=READY`），MVP 演示通常只验证已有标签匹配。
3. 产品尚未确认 S3 是否应像 S1/S2 一样默认落库未命中生成项（设计决策 D013）。

### 完善建议

1. **产品确认**：S3 生产环境默认值应为 `true` 还是 `false`；若开启，需明确人工审核门禁（D010）。
2. **分环境配置**：在 `configs/prod.yaml`（或环境变量）显式设置 `scene.s3.auto_create_unmatched: true`，并在部署 checklist 中验收。
3. **联调验证**：
   - 开启后跑通 `test_s3_pipeline_*` 中带 `auto_create=True` 的用例；
   - 确认新建标签 `vector_state=PENDING` 时 Job 重试、向量就绪后可发布；
   - 确认 `PreValidator` 对新标签的安全门禁在创建前生效（整单校验，任一失败则不创建任何标签）。

### 验收标准

- [ ] 生产配置明确写入 `auto_create_unmatched` 且与产品决策一致
- [ ] 开启后 E2E：未命中标签 → 创建 → 向量 READY → 结果可发布
- [ ] 关闭时行为与现有集成测试一致（新标签不出现在 `result.tags`）

## S3-P2：完整规则引擎（当前仅 `provisional-rule-mvp-1`）

### 含义

设计文档 §7 将 Validation 拆为两层：

1. **MVP Validation**（已实现）：EvidenceRef 可回查、新标签安全、模态完整性等门禁。
2. **完整规则引擎**（未接入 S3 管线）：按 `policy_version` 插件化加载 `ConfidencePolicy`，用证据/一致性/稳定性系数计算 `final_confidence`。

当前 S3 实际行为：

- `policy.confidence.version` 默认为 `provisional-rule-mvp-1`，仅写入结果的 `policy_version` 字段
- `TagCommitter` 直接使用 LLM 的 `model_score` 作为 `final_confidence`，**未调用** `ConfidencePolicy.score()`
- `RuleEngineLoader` 与 `build_rule_mvp_1()` 存在，但未在 S3 pipeline 或 factory 中装配

### 相关代码

| 位置 | 说明 |
|------|------|
| `configs/base.yaml` | `policy.confidence.version: provisional-rule-mvp-1` |
| `src/label_agent/validation/rule_engine/base.py` | `RuleEngineLoader` |
| `src/label_agent/validation/rule_engine/policies/rule_mvp_1.py` | MVP 规则包构建 |
| `src/label_agent/domain/confidence/default_policy.py` | `ProvisionalRuleMvp1` 公式实现 |
| `src/label_agent/scenarios/s3_content/pipeline.py` | 无 `ConfidencePolicy` 注入与调用 |
| `docs/agent_implementation_design.md` §7 | 分期设计与公式定义 |

### 候选公式（未定稿）

```text
Final_Conf = calibrated_model_score
             × min(evidence_factor, consistency_factor, stability_factor)
```

系数需从配置中心加载（`policy.confidence.rule_mvp_1.coefficients`），结果需保留原始模型分数与各系数以便回放。

### 完善建议

1. **等待 D001 冻结**：产品/算法确认系数、阈值及 `provisional` → 正式 `policy_version` 的切换时机。
2. **接入点**：在 `EntityResolver` 之后、`TagCommitter` 之前（或 `TagCommitter` 内部）调用 `ConfidencePolicy.score()`，用返回值覆盖 `final_confidence`。
3. **注册表扩展**：`ConfidencePolicyRegistry` 注册新版本策略；`RuleEngineLoader.load(policy_version)` 按配置热切换。
4. **ReviewRouter**：置信度低于阈值或证据因子异常时路由人工审核（D010，独立配置）。
5. **回归**：保留 `provisional-rule-mvp-1` 作为基线，新增策略版本需有金标集对比 `final_confidence` 分布。

### 复杂度评估：**中**

- 核心计算逻辑已有 `ProvisionalRuleMvp1` 样板；
- 主要工作量在：EvidenceBundle 组装、管线注入、配置中心系数、ReviewRouter 联动、测试与回放工具。

### 验收标准

- [ ] S3 pipeline 按 `policy.confidence.version` 加载并应用 `ConfidencePolicy`
- [ ] 结果 JSON 含 `calibrated_model_score`、各 factor 及 `policy_version`
- [ ] 切换 `policy_version` 无需改 pipeline 代码
- [ ] 产品冻结后移除结果中的 `provisional` 标记流程

## S3-P3：远程媒体域名白名单（`MediaGuard` 为空）

### 含义

S3 支持文本、图片、视频及混合输入。远程 HTTP(S) 媒体 URI 下载前须经 `MediaGuard` 校验，防止 SSRF、私网访问与超大文件。

当前装配：

```python
# mvp_scene_factory.build_s3_handler()
media_guard = MediaGuard(allowed_domains=set(), max_bytes=20 * 1024 * 1024)
```

`allowed_domains=set()` 表示**任何远程域名都会被拒绝**（抛出 `SsrfProtectionError`）。本地文件路径与 `data:` URL 不受白名单限制，因此 MVP 本地演示通常不受影响；**生产环境若 Job 携带 CDN/OSS 图片或视频 URL，感知阶段会失败**。

对比：S4 已从配置与环境变量加载白名单：

- `scene.s4.media_allowed_domains`
- 环境变量 `S4_MEDIA_ALLOWED_DOMAINS`

S3 **尚未**提供对等的 `scene.s3.media_allowed_domains` 配置项。

### 相关代码

| 位置 | 说明 |
|------|------|
| `src/label_agent/perception/media_guard.py` | 域名白名单 + 私网 IP 拦截 + 体积上限 |
| `src/label_agent/bootstrap/mvp_scene_factory.py` | S3 硬编码空白名单 |
| `src/label_agent/bootstrap/s4_scene_factory.py` | S4 从配置/环境变量加载（可参考） |
| `scripts/mvp_common.py` | `build_media_guard()` 同样空白名单 |
| `configs/base.yaml` | S4 有 `media_allowed_domains`；S3 无对应项 |

### 完善建议

1. **配置项**：在 `configs/base.yaml` 的 `scene.s3` 下增加：
   ```yaml
   scene:
     s3:
       media_allowed_domains: []   # 生产填入 CDN/OSS 域名
       max_media_bytes: 20971520   # 可选，与 S4 对齐
   ```
2. **Factory 改造**：参照 `s4_scene_factory.py`，在 `build_s3_handler()` 中读取配置并支持环境变量（如 `S3_MEDIA_ALLOWED_DOMAINS`）。
3. **DNS 解析后二次校验**：`media_guard.py` 注释已标注「生产实现需补充解析后校验」——域名形式 hostname 当前仅做白名单匹配，建议在完善项中一并跟踪。
4. **运维清单**：向安全/运维收集允许的域名（如 `*.oss-cn-*.aliyuncs.com`、企业 CDN 域名），写入各环境 yaml 或 K8s ConfigMap。
5. **测试**：增加单元/集成测试——白名单内 URI 可下载、域外 URI 抛 `SsrfProtectionError`、私网 IP 直连被拒绝。

### 复杂度评估：**低**

- `MediaGuard` 与 S4 装配模式已存在，S3 主要是配置贯通与测试。

### 验收标准

- [ ] S3 远程图片/视频 URL 在生产白名单域名下可正常感知
- [ ] 非白名单、私网、超大文件请求被稳定拒绝且错误可观测
- [ ] 本地文件与 `data:` URL 行为不变

## 实施优先级建议

```text
生产若要接远程媒体 URL     → 优先 S3-P3（低复杂度，硬阻塞）
生产若要自动创建新标签     → S3-P1（低复杂度，需产品确认）
置信度口径与审核策略定稿   → S3-P2（中复杂度，依赖 D001）
```

建议顺序：**P3 → P1 → P2**。P3 不依赖产品决策；P1 与向量闭环已打通，切换配置即可；P2 需等产品/算法冻结后再接入，避免反复改系数。
