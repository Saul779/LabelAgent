# 推荐搜索整体架构设计

# 整体架构

### 核心设计

一切通过标签匹配。AI Agent 离线完成语义理解，生成标签向量；在线链路零 LLM 调用，通过标签匹配实现搜索与推荐。

## 内容生产 → 用户搜索

|环节|说明|
|---|---|
|**内容供给侧**|商品/任务/动态等内容进入系统|
|**AI Agent 打标**|多模态理解内容，抽取标签，生成标签向量|
|**标签入库**|标签向量存 Milvus，标签 ID 写 ES 商品文档|
|**用户搜索**|Query 向量化 → 找相似标签 → 标签 ID 过滤 ES → 返回结果|

### 商品/任务/动态打标

|步骤|输入|处理|输出|存储|
|---|---|---|---|---|
|内容理解|文本/图片/视频/商品|文本 Embedding、图像 Embedding、多模态融合|内容语义表示|—|
|标签抽取|内容语义表示|匹配标签库、生成新标签、置信度打分|标签列表 \+ 置信度|—|
|向量生成|标签描述 \+ 内容本身|标签描述向量化|标签向量|Milvus|
|数据同步|标签向量 \+ 标签 ID|Kafka 消息总线|标签变化事件|MQ → 后端服务更新 ES|

### 用户搜索

|步骤|输入|处理|输出|
|---|---|---|---|
|搜索联想|用户输入前缀|Trie 树前缀匹配|联想词列表|
|关键词提取|完整 Query|分词、停用词过滤、关键词识别|关键词列表|
|标签向量查询|关键词|查 Redis 缓存，未命中查 Milvus|关键词对应的 tag\_vector|
|相似标签检索|query\_vector|Milvus ANN 检索 `tag_vectors`|相似标签 ID 列表（top 20）|
|ES 精准检索|标签 ID 列表 \+ 关键词|`terms` 过滤标签 ID \+ BM25 关键词检索|候选商品列表|
|排序去重|候选商品 \+ 多维度特征|GBDT 精排、多样性重排、业务规则|最终搜索结果|

**兜底策略**：纯数字、型号精确匹配时，跳过向量检索，直接走 ES 关键词检索。



## 用户理解 → 智能推荐

|环节|说明|
|---|---|
|**用户行为采集**|点击、收藏、购买、浏览、搜索等行为日志|
|**数据计算**|Spark/Flink 聚合用户画像特征|
|**AI Agent 画像打标**|分析行为模式，抽取用户兴趣标签，生成用户标签向量|
|**标签匹配**|用户标签与内容标签双向匹配|
|**智能推荐/推送**|用户浏览时推荐内容，发布内容时推送目标用户|

### 用户画像打标

|步骤|输入|处理|输出|存储|
|---|---|---|---|---|
|行为采集|用户点击、收藏、购买、停留时长|实时写入 Kafka|原始行为日志|Kafka|
|数据存储|原始日志|落盘 Hive，实时写入 HBase|行为序列|Hive / HBase|
|数据计算|行为序列|Spark 聚合：频次、时间衰减、偏好强度|用户画像特征|—|
|画像理解|用户画像特征|AI Agent 分析行为模式、兴趣偏好、消费意图|用户兴趣表示|—|
|标签抽取|用户兴趣表示|匹配标签库、生成用户专属标签、置信度打分|用户标签列表 \+ 权重|—|
|向量生成|用户标签列表 \+ 权重|加权平均标签向量|user\\\_vector|Milvus|
|数据同步|用户标签 ID 列表 \+ 权重|写入 Redis / MySQL|用户标签画像|Redis / MySQL|

### 大数据推荐

|场景|触发条件|匹配方向|核心动作|输出|
|---|---|---|---|---|
|**用户浏览推荐**|用户打开 APP / 页面|用户标签 → 内容标签|用户标签向量找相似内容标签 → ES 过滤检索 → GBDT 精排|推荐列表|
|**发布任务/动态推送**|创作者/系统发布内容|内容标签 → 用户标签|内容标签向量找相似用户标签向量 → 过滤活跃用户 → 触达|推送消息|

#### 用户浏览推荐

|步骤|处理|说明|
|---|---|---|
|获取用户标签|查 Redis `user:tags:{user_id}`|取出用户高权重标签 ID 列表|
|标签扩展|查 Milvus `tag_vectors` ANN 检索|找语义相似标签，扩大召回|
|内容召回|ES `terms` 过滤标签 ID \+ 类目/价格过滤|召回候选内容|
|曝光过滤|排除用户近期已曝光内容|查 HBase 用户曝光历史|
|精排|GBDT 模型打分|特征：标签匹配度、CTR、时效性、质量分|
|重排|多样性控制 \+ 新鲜度加权 \+ 业务规则|MMR / 时间衰减 / 插播|
|返回|推荐列表|写入 Redis 缓存|

#### **发布任务/动态推送**

|步骤|处理|说明|
|---|---|---|
|用户匹配|Milvus ANN 检索：内容标签向量 → 相似用户标签向量|找兴趣匹配的用户群|
|用户过滤|查 Redis 用户活跃度、触达频次、免打扰设置|排除不活跃/已频繁触达用户|
|生成推送|组装推送文案、链接|可结合用户偏好个性化文案|
|消息触达|推送 / 站内信 / 短信 / 邮件|根据渠道优先级和用户偏好选择|

## 标签向量设计

### Milvus 的 tag\_vectors 结构

|字段|类型|说明|
|---|---|---|
|**id** \(主键\)|VARCHAR / INT64|标签唯一标识，如 `tag_001`|
|vector|FLOAT\_VECTOR\[768\]|标签语义向量|
|tag\_name|VARCHAR|标签名称，如"复古胶片风"|
|category|VARCHAR|标签类目，如"视觉风格"|
|level|INT8|标签层级，1/2/3级|
|status|INT8|状态，1有效/0失效|

### 查询方式

```Python
Milvus 检索：
{
    "collection": "tag_vectors",
    "vector": [0.12, -0.34, ...],   ← query_vector
    "topk": 20,
    "output_fields": ["id", "tag_name", "category"]
}

返回：
[
    {id: "tag_001", tag_name: "复古胶片风", distance: 0.95},
    {id: "tag_042", tag_name: "柯达胶卷感", distance: 0.88},
    ...
]
```



## Q\&A

#### 用户搜索内容怎么与标签匹配？

通过Redis缓存关键词与标签的映射关系

1. AI Agent在打标的同时，提取标签关键字，搜索中台写入到Redis

2. 查询未命中的关键词，走向量搜索，并异步回写入Redis缓存
