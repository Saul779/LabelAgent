## 1. 信息缺失

| 缺失项 | 说明 | 影响 |
|--------|------|------|
| 规则引擎定稿 | 补充明确「待产品完善」；维度、阈值、公式均未冻结 | Validation 无法验收；只能预留钩子 |
| 权限模型 | 仍无角色权限矩阵 | 审核与认证后台安全边界不清 |
| 异常流程 | 模态失败、超时、审核超时仍未定义 | 生产稳定性风险 |
| 数据模型细节 | 字段、主键、版本、别名是否可独立存输出未定 | 建表与索引策略 |
| 分类层级 | 一级/二级是否强制仍不明 | S3 输出 schema |
| 内容分类全集 | 商品/任务/日常与「校园生活…」十类如何映射 | 词表建设 |
| 职业/技能词表内容 | 补充要求「已有标签」匹配，但词表条目未给出 | S1/S2 无法联调 |
| 非功能指标 | 性能/成本具体数字仍缺 | 无法压测验收 |
| 埋点方案 | 仍空 | 30min 目标无法归因 |
| 人机标签冲突 | UGC vs AI 优先级仍不明 | 推荐口径 |
| 重打标策略 | 词表变更是否重跑仍不明 | 成本与一致性 |
| 证书合规 | 伪造/过期证书处理未定义 | 认证风控 |
| 新标签治理指标 | Agent 新标签的命名规范、合并/停用 SLA 未定义 | 词表可能持续膨胀 |
| S4 类目稳定标识 | 商品类目表只有一级/二级名称，无 `category_id/parent_category_id/taxonomy_version` | 导入服务必须生成并持久化映射；不能直接用二级名称做主键 |
| S4 性能成本阈值 | 已确认质量指标，但 P95 时延和单商品成本绝对值未冻结 | 不阻塞功能开发，阻塞容量与上线验收 |

## 2. 技术风险

| 风险 | 类型 | 说明 | 建议缓解 |
|------|------|------|----------|
| 多场景并行复杂度 | 技术 | S1/S2/S3/S4 同时演进，管线、Prompt 和词表膨胀 | 统一 Orchestration；分场景 Prompt/词表；共享 Perception；S4 独立 Handler |
| 视频/音频全量成本 | 成本 | 补充要求必须解析，token 与算力显著上升 | 异步 Job；抽帧/限时长等**工程手段**；设预算告警（不取消需求） |
| 规则引擎未定稿 | 产品/技术 | 质量门禁缺失可能导致脏标签进入推荐 | 过渡期仅做 schema+词表合法性；完整规则产品定稿后再开 |
| 别名计入 5 额 | 数据 | 同簇多名称占额曾导致稀释 | **已确认：同簇只保留 1 个**；实现需在 Prompt 后处理做簇去重 |
| 输出不稳定 | 技术 | 无完整规则引擎时一致性更难保 | 评测集 + 分场景回归；人工抽检 |
| 认证材料隐私 | 安全 | 证件类图片进模型与日志 | 脱敏、加密存储、短期保留、审计 |
| 并发幂等 | 技术 | 认证重复提交与动态高峰 | Job 幂等键含 scenario + 业务主键 |
| 匹配效果 | 业务 | 别名直接入库可能造成召回碎片化 | 索引侧可选「别名→标准」归一（见 Q005 修订） |
| 自动建标签污染 | 数据/业务 | 新标签立即生效，误建或近义重复会直接进入推荐 | 创建前标准+别名近义查重；唯一约束；记录来源；后台支持合并/停用 |
| 并发重复创建 | 技术 | 多个 Job 可能同时创建同一或近义标签 | 归一化名称唯一索引 + 原子 upsert；冲突后回读复用 |
| Tag Service 缺失 | 架构/排期 | 标签无统一事实源，无法可靠查重、创建、合并和发事件 | P0 建设标签服务并先冻结接口 |

## 3. 需要产品确认的问题

### Q001

- **问题：** 用户角色与权限矩阵如何定义？
- **为什么需要确认：** 后台与安全边界。
- **影响范围：** 用户系统、管理后台。
- **建议方案：** 普通用户 + 运营审核 + 管理员先落地。

### Q002（已按补充修订）

- **问题：** ~~视频是否打标~~ → **改为：视频/音频解析的工程边界**（时长上限、抽帧数、失败降级顺序）是什么？
- **为什么需要确认：** 业务要求必须解析，但需可运营的成本与 SLA。
- **影响范围：** Perception、队列、成本。
- **建议方案：** 业务不取消；工程设 max 时长/关键帧数；失败则记录缺口并人工或重试，**不得默认整单跳过视频模态而不记录**。

### Q003

- **问题：** 商品/任务/日常 与现有「校园生活…」等一级分类如何统一？
- **为什么需要确认：** S3 词表根基。
- **影响范围：** 分类库、列表筛选。
- **建议方案：** 「商品/任务/日常」为内容业务域；兴趣十类为日常域下分类；商品/任务用独立分类树或标签分组。

### Q004

- **问题：** 二级分类是否强制？
- **为什么需要确认：** S3 schema。
- **影响范围：** Agent 输出、DB。
- **建议方案：** MVP 一级强制，二级可空。

### Q005（部分确认）

- **问题：** 输出允许标准或别名标签，合计 ≤5；**推荐索引时是否归一到标准标签？**
- **为什么需要确认：** 展示名可为别名，召回口径需统一。
- **影响范围：** 打标结果、召回、去重。
- **已确认部分：** **标准与其别名不可同时占额度**（同标准簇只输出 1 个名称）。
- **建议方案（索引侧仍待确认）：** 存储保留 `type=standard|alias` 与 `canonical_tag_id`；召回默认按标准 ID；列表展示可用 Agent 选出的名称。

### Q015（已确认 ✔）

- **问题：** 单次动态输出中，标准标签与其别名是否可同时占用多个名额？
- **确认结论：** **不可**。同一标准簇只保留 **1** 个标签名（标准或别名二选一），计入 5 个额度中的 1 额。
- **实现要求：** Labeling 后处理（或 Validation Hook）按 `canonical_tag_id` 去重，保留置信度最高项；Prompt 中需明确禁止同簇多输出。
- **影响范围：** S3 输出契约、后处理、评测用例。
- **状态：** 已关闭，写入 PRD v0.2.1。

### Q006

- **问题：** 规则引擎完善前，何种结果必须进人工审核？
- **为什么需要确认：** 规则未定稿仍需门禁。
- **影响范围：** 审核队列、画像污染风险。
- **建议方案：** 过渡期：无法解析、分类不在库、标签查重失败、空匹配认证申请 → 人工；无近义标签时允许创建新标签。

### Q007

- **问题：** 用户手动标签与 AI 标签冲突时以谁为准？
- **为什么需要确认：** 特征口径。
- **影响范围：** 内容索引、画像。
- **建议方案：** 分路权重，UGC 默认可更高。

### Q008

- **问题：** 「30min 成交」统计口径与归因？
- **为什么需要确认：** 验收推荐价值。
- **影响范围：** 埋点、实验。
- **建议方案：** P50 成交时长 + 推送漏斗。

### Q009（已按补充修订）

- **问题：** ~~认证是否延后~~ → **三场景 MVP 内的优先级与并行度？**（先 S3？先 S1/S2？还是三条并行？）
- **为什么需要确认：** 资源与排期。
- **影响范围：** 里程碑。
- **建议方案：** 并行基建（Router/Perception/词表）+ 先交付 S1/S2 图文路径与 S3 图文，视频/音频紧随同迭代（补充要求存在则不可砍业务，但可分能力里程碑）。

### Q010

- **问题：** 词表变更是否触发历史重打标？
- **为什么需要确认：** 成本与一致性。
- **影响范围：** Job、成本。
- **建议方案：** 近 N 天/高曝光增量重打。

### Q011

- **问题：** 职业标签库、技能标签库、内容标签库是否同一 Tag 服务多域，还是三套库？
- **为什么需要确认：** S1/S2/S3 词表隔离与复用。
- **影响范围：** 数据模型、后台、RAG。
- **建议方案：** 统一 Tag 服务，`domain ∈ {career, skill, content}` 隔离。

### Q012

- **问题：** 模型选型、备用模型、JSON 失败降级？
- **为什么需要确认：** 稳定性与成本。
- **影响范围：** LLM 层。
- **建议方案：** 主备模型；失败重试 1 次后人工/兜底。

### Q013

- **问题：** 未分类内容在推荐中的策略？
- **为什么需要确认：** 冷启动体验。
- **影响范围：** 召回。
- **建议方案：** 少量探索 + 主力需有效标签。

### Q014

- **问题：** 消息触达通道与频控？
- **为什么需要确认：** 转化闭环。
- **影响范围：** 推送。
- **建议方案：** v1.1 站内信 + Push，日上限可配。

### Q015（已确认，见上）

> 正文已上移至「已确认」区块，此处不重复。

### Q017（已确认 ✔）

- **问题：** Agent 是否可创建新标签，以及如何生效？
- **确认结论：**
  1. Agent **可以创建新标签**，但不可创建新分类；
  2. 创建前必须检索现有标准标签与别名并做近义查重；
  3. 无可复用标签时，创建新的标准标签并**立即进入正式词表**；
  4. 新标签可直接用于当前打标结果及后续推荐。
- **实现要求：** 新建标签生成 `canonical_tag_id`；归一化名称唯一约束与原子创建；记录来源 Job、模型、Prompt、证据；后台支持停用、合并和改名。
- **影响范围：** S1/S2/S3 Labeling、Retriever、Tag Service、Validation、推荐索引、管理后台。
- **状态：** 已关闭，写入 PRD v0.3。

### Q018（已确认 ✔）

- **问题：** 用户画像打标是否属于 Agent，Tag Service 是否已经存在？
- **确认结论：**
  1. 用户画像打标**不纳入本 Agent**；历史建议的 S4 编号已释放，2026-08-19 起 S4 正式指代商品打标；
  2. 当前不存在 Tag Service，需作为 P0 基础模块建设。
- **影响范围：** Agent Router、Tag Service、版本排期。
- **状态：** 已关闭。

### Q016（新增）

- **问题：** 规则引擎产品完善的交付时间与最小能力集（是否含证据校验、自洽性、Final_Conf）？
- **为什么需要确认：** 补充将其从定稿能力中撤出，需重新排期。
- **影响范围：** Validation Hook、质量指标。
- **建议方案：** 先冻结最小能力（schema + 在库校验）；原四维公式作候选方案进入产品评审，不定稿不开发深层规则。

## 5. 结论

需求已明确：**Agent 负责 S1 职业认证、S2 技能认证、S3 多模态动态打标、S4 商品打标；分类只匹配，标签优先复用并允许查重后自动创建。** S4 只返回候选分类建议，不创建正式分类；其 0.85 阈值与双模型复核已冻结。S3 完整规则引擎仍不是当前已定稿模块。

统一 Job/Router、S1/S2/S3/S4 Prompt、Perception 和审核输出已形成底座；同时继续建设 Tag Service/类目知识持久化发布接口。用户画像打标不纳入本 Agent。S4 已使用独立 `ProductLabelResult` 完成 MVP，生产类目富化与真实模型验收仍需推进。
